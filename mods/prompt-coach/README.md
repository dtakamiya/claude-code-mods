# prompt-coach

送ったプロンプトに対象・範囲・完了条件の欠けなどがあるとき、送信直後に 1 行で指南する mod です。**読み取り専用**で、送信文は書き換えず、止めもしません。判定はヒューリスティクス（文字列の観察）だけで、モデルは呼びません。

```
/plugin install prompt-coach --marketplace dtakamiya/claude-code-mods
```

- 人が Enter で送った直後（`prompt.submit`）に判定し、当たったときだけ status 行に 1 行出します。当たらなければ何も出ません。
- 表示はターン完了（`turn.complete`）で消えます。サブエージェントのターン終了では消しません。
- 表示例: `💡 「これ」だけでは対象が伝わりにくい。ファイル名かエラー文を添えると手戻りが減りやすい`
- 文言は「〜しやすい」「〜減りやすい」止まりで断定しません。手戻りが減るという効果は仮説で、検証していません。

設計と根拠は `docs/design/proposals/2026-10-23-prompt-coach.md` にあります。

## 4 つのルール（優先順位順）

1 通に出すのは最大 1 行・1 ルールです。上から順に見て、最初に当たったものを出します。

| ルール | 当たる条件（目安） | 表示の趣旨 |
|---|---|---|
| `vague-target` | セッション内で人が送った最初の 1 通で、指示語（これ・それ・あれ・この・その）を含み、パス・拡張子・英字の識別子・バッククォートのコード・エラー文らしい語が無い | 対象（ファイル名かエラー文）を添える |
| `no-scope` | 広い動詞（リファクタ・整理・改善・最適化・いい感じ・きれいに など）を含み、全体が 40 字未満で、具体的な対象が無い | 範囲と守る制約を添える |
| `multi-task` | 読点・カンマ・改行・セミコロン・行頭の箇条記号で区切った断片が 4 つ以上あり、コードを含まない | 1 通 1 ゴールに分ける |
| `no-done-criterion` | 実装・追加・作って・作成・対応 を含み、全体が 30 字未満で、テスト・通る・ように・期待 などの完了条件語が無い | 完了の判定を添える |

判定の各しきい値（40 字・30 字・4 断片・1 セッション 2 回・直近 10 通）は仮置きの定数です。実測で調整します。

## 黙る条件

次のどれかに当たる送信では、表示しません。スラッシュコマンド・`isMeta`・人以外の起源の送信は通数にも数えません。承認語・貼り付け・停止中の送信は通数には数えます。

- スラッシュコマンド（`/` で始まる送信、または command を伴う送信）
- `isMeta` の送信
- 人の Enter 以外の起源（通知・ピア・定期実行・別プラグインなど）。Remote Control 経由（`bridge`）も、端末の status 行で見えないため黙ります
- 承認・継続だけの短い送信（「はい」「OK」「続けて」「進めてください」など。複数語でも承認語だけならこれに当たる）。通数には数えます
- コードフェンスを含む送信、または 5 行以上かつ 300 字超の貼り付け（ログ・差分など）
- `/coach off` で停止しているとき（通数は数えます）

## 頻度の上限

- 同じルールは 1 セッションに **2 回まで**。
- 全体では直近 **10 通に 1 回まで**。表示した通の後の 9 通は、どのルールも出しません（10 通目から再び出せます）。
- 上限に達したルールは、次に当たる優先順位のルールに譲ります。
- セッション開始（`session.start`）で、通数・上限・停止状態はすべて初期値に戻ります。

## `/coach on` / `/coach off`

```
/coach off   このセッション内の指南を停止する
/coach on    停止を解除して再開する
```

停止状態はメモリにだけ置き、ファイルには保存しません。Claude Code を終了すると、次のセッションは既定の「有効」から始まります。

## 権限（読み取りのみ）

- 読むのは `prompt.submit` の送信文（`text`）・起源（`origin.kind`）・`isMeta`・command の有無だけです。
- 送信文は判定にだけ使い、表示文にも本文は含めません。`next(e)` には無改変で渡します。
- 状態（通数・上限の記録・停止フラグ）は mod 内のメモリだけに置きます。
- `$.model`（モデル呼び出し）、`$.fs` の書き込み、`$.process`、`$.http` は使いません。外部への通信もしません。
- 判定に失敗したときは固定文言を debug ログに残すだけで、送信は通します。例外の中身（送信文を含みうる）は出しません。

## 既知の制約

- **`$.ui.status` の表示は目視未確認です。** 表示位置・消えるタイミング・長さの見え方は、`claude --plugin-dir` で目視していません。
- 読点が 4 つ以上あれば、1 つのゴールの文でも `multi-task` が出ます（例: 対象パスを含む条件付きの依頼）。
- 英字 2 文字以上の語（`CI` など）は「具体的な対象」とみなすため、指示語の判定を外すことがあります。
- 指示語を含む最初の 1 通だけを見ます。セッションの途中から始めた依頼は対象外です。
- 「指南した送信の後に手戻りが減る」という効果は、この mod では測っていません。

## 開発

`claude plugin validate mods/prompt-coach` と `claude plugin test mods/prompt-coach` を実行します。型検査は `scripts/typecheck.sh prompt-coach <claude-code.d.ts>` です。手順は `CLAUDE.md` にあります。

動作確認済みバージョン: Claude Code 2.1.309（validate / test / tsc）。目視確認は未実施です。
