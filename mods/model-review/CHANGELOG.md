# Changelog

version は `.claude-plugin/plugin.json`。0.14.0 以前は版ごとの記録を残していないため、`git log -- mods/model-review` の PR 単位で示す（#19〜#39）。0.14.1 以降は版ごとに記録する。

## 0.26.0
- 会話が伸びるにつれた 1 ターンあたりの費用の推移を、コストの節とテキストレポートに出す（#84 段階 1）。メインのターンを古い順に最初の `GROWTH_WINDOW_TURNS`（10）と直近の 10 に分け、「1 ターンあたり $0.04 → $0.19（プロンプト 18k → 142k tokens）」と事実だけを並べる（`growth.ts` の純粋関数。▲ の指摘にも次の一手にもしない）。ターンが `GROWTH_MIN_TURNS`（20）に満たないときは出さない。`/compact` の直後のターン（`afterCompact`）で区切り、最後の compact の後だけで推移を見て、compact の前後は「compact の前 $X → 後 $Y」と別の行に並べる（直後のターンは再構築を含むので比べない。各側 3 ターン未満なら出さない）。単価不明のターンはコストの平均から、プロンプト長が取れないターンはその平均から除く。畳み込み済みのターンは入らないので、その旨を注記する。段階 2（`/compact` を次の一手の候補にする）は未実装。読取専用。見た目は目視未確認。

## 0.25.0
- plan mode のターンを、モデル起因の過剰から外した（#82 の段階 1）。`prompt.attachment`（`type: 'plan_mode'`）を観察して、進行中のメインのターンの下書きに印を付け（`recorder.ts` の `markPlanMode`）、`TurnRecord.planMode`（任意項目、真偽のみ。計画ファイルのパスは記録しない）に残す。観察のみで `next(e)` をそのまま返し、reminder の結果は書き換えない。`analyze.ts` の `isModelOverspec` は `planMode` のターンを外す。effort 起因の過剰は外さない（計画でもモデルより effort が下げやすいため）。plan mode のターンがあれば注記に件数を 1 行出す。サブエージェントのループ・ターンの外で届いた reminder は印を付けない。段階 2（`/model opusplan` の候補）は件数がそろってから。読取専用。見た目は目視未確認。

## 0.24.1
- 1 ターンの中でモデルが替わると最後のモデルにまとめて計上される問題を直した（#83）。`recorder.ts` が応答ごとにモデル別の内訳（トークン・推定コスト・応答数）を持ち、2 モデル以上が応答したターンだけ `TurnRecord.byModel` に残す（1 モデルのターンは状態を増やさない）。モデル × effort の表と畳み込み（`archive.ts`）は `byModel` があればモデルごとに分け、混ざったターンは各モデルの行に 1 件ずつ数える（行のターン数の合計はターン数より増えうる）。`byModel` のない古い記録は従来どおり。ターン開始時に `$.session.model()` を読み、応答のモデルが食い違った応答を数えて `divergedSteps` に残し、注記に「食い違った応答を含むターンが N 件（フォールバックなどの可能性。推定）」の 1 行を出す。原因は断定せず、指摘には使わない。Haiku / Sonnet 換算と過剰の判定は、これまでどおりターン単位（最後のモデル）のまま。見た目は目視未確認。

## 0.24.0
- サブエージェントを種類別（Explore / general-purpose / 独自エージェントなど）に集計する（#72）。`agent.spawn` の結果で `agentId → subagentType` を覚え（`agenttype.ts` の純粋な reducer）、reload で表が消えた後は `$.agent.list()` の `type` で補う。`TurnRecord.agentType`（任意項目、種類の名前だけ。説明・プロンプトは記録しない）に残し、ループ別の節のサブエージェントの下に種類別の行（ターン数・モデル・ヒット率・推定コスト）を出す（種類が 2 つ以上のとき）。「サブ」の指摘には、コストが最も大きい種類を名前で添える。種類が分からないターンは「種類不明」にまとめ、推測しない。読取専用。見た目は terminal / desktop とも目視未確認。

## 0.23.1
- effort が数値で届いたときの扱いを直した（#85）。`recorder.ts` は数値を `String()` で文字列にせず `n:32000` の形で残し（`effort.ts`）、文字列の effort とは別のグループにする。数値は high などに読み替えない（公式に対応表がなく、数値が届く条件も未検証のため）。表（モデル × effort・切替・過剰の行）では「数値 32000」と書き、数値のターンがあれば指摘の節に「effort が数値のターン N 件は、effort による過剰・不足の判定に入れていません」の 1 行を出す。見た目は terminal / desktop とも目視未確認。

## 0.23.0
- コストの内訳（入力・出力・キャッシュ書込・読込のどれが効いているか）を出す（#75）。`pricing.ts` に `priceUsageParts`（4 種の推定額。合計は `priceUsage` と一致、Haiku 5.5 の単価段は応答ごとに判定）を足し、`TurnRecord.costParts` と `ArchivedTurns.costParts` / `partsMissingTurns` に残す（畳んだ後も合計が合う）。コストの節とテキストレポートに「内訳: 書込 58% · 出力 25% · 読込 12% · 入力 5%」を 1 行出し、書込または出力が半分以上のときは、既存の注意（書込の連続）・指摘（過剰・不足）を指す手がかりを添える（`breakdown.ts`）。書込は 5 分単価で、TTL の幅があることを注記する。単価不明のターンと、0.23.0 より前に記録した内訳のないターンは内訳から除き、その数を注記に出す。純粋関数のみで読取専用。見た目は terminal / desktop とも目視未確認。

## 0.22.0
- ターンの指し示しを、内部の turnId から利用者が数えられる形に変えた（#70）。`TurnRecord` に任意項目 `mainSeq`（メインのターンの通し番号。サブエージェントは親のメインのターンの番号）と `completedAtMs`（完了時刻、`$.clock.now()`）を足し、`turn.complete` で `stampTurn` が付ける。通し番号は畳んだ分も数えるので、`archive.ts` で畳んだ後もずれない。表示は、高コストターンが「#37（12 分前）」、指摘・切替の行が「#37（8 ターン前）」（直近は「最新」）、サブエージェントは「#37 の中のサブエージェント」（`turnref.ts`）。通し番号のない古い記録は従来どおり「ターン <turnId>」で表示する。依頼の本文は記録・表示しない。見た目は terminal / desktop とも目視未確認。

## 0.21.0
- 意図して選んだモデル・effort の指摘を、種類ごとに止める設定 `mutedConcerns`（既定: 空）を追加（#74）。英名（`overspec` など）か短い名前（過剰など）をカンマ・読点・空白区切りで書き、大文字小文字・全角/半角（NFKC）の違いは同じ名前として読み、知らない名前・空・文字列以外は無視する（`mute.ts` の `readMutedConcerns`）。止めた種類は結論行の件数・色から外し、指摘の節には「止めている指摘（設定 mutedConcerns）: 過剰 3 / 40 件」の 1 行だけを残す（件数は指摘の節と同じ表記。該当がなくても種類名は出し、窓より前にだけ該当したものは「（過去）」と添える）。ペインとテキストレポート（`/model-review copy` を含む）で同じ扱い。`userConfig` に複数選択の型がないため文字列で受ける。設定の見た目・ペインの 1 行は目視未確認。

## 0.20.0
- 指摘が「いま続いている」のか「過去のもの」なのかを分けた（#69）。指摘ごとに「最後は N ターン前」（メインのターンで数える）を添える。結論の ▲ と件数・色は、メインの直近 `RECENT_CONCERN_MAIN_TURNS`（20、仮置き）ターンに該当がある指摘だけで決め、窓より前にだけ該当した指摘は「過去の指摘（メインの直近 20 ターンには該当なし）」の下に色なし・次の一手なしで並べる。過去の指摘だけなら結論は「✓ 結論: 目立った指摘なし（過去の指摘 N 種）」。委譲はもともと直近の窓で判定しているので常に直近扱い。ペインとテキストレポートは同じ判定（`conclusion.ts`・`isRecentConcern`）を使う。見た目は terminal / desktop とも目視未確認。

## 0.19.0
- コマンドの引数を見直した（#76）。`/model-review help` で使える引数の一覧、`/model-review text` でペインを置ける画面でもテキストレポートを返す。知らない引数（`cpy` などの打ち間違い）では黙ってペインを開かず、help を案内する（記録も読まない）。引数の判定（`parseCommandMode`）は前後の空白・大文字小文字を無視する。コマンドは `argumentHint`（`[copy|text|help]`）つきで登録する。ヒントの見た目は目視未確認。

## 0.18.0
- 指摘ごとに「次の一手」の候補を 1 行添える（#68）。文言は純粋関数（`nextstep.ts`）で作り、ペインとテキストレポートで共用する。過剰（モデル起因・メイン）は `/model sonnet` を、軽作業の平均の 1 ターンあたりの差額・再構築コスト（「いま切り替えたら」と同じ見積り）・回収ターン数（`whatif.ts` と同じ計算）つきで示し、回収に `MAX_RECOVERABLE_TURNS`（10、仮置き）を超えるときは「切替の元は取りにくい」と添える。直近のメインがすでに Sonnet 以下なら対応不要かもしれないと書く。`/model`・`/effort` はメインにだけ効くため、サブエージェント由来の指摘には定義側の設定を示す。過剰（サブエージェント）は定義の `model`、過剰（effort）は `/effort high` 以下（キャッシュが維持されるモデルかどうかも添える）、不足は effort を上げる・Sonnet 以上、委譲は Explore などのサブエージェント、サブはサブエージェント定義の `model`、切替はまとめるのが目安、を候補にする。コマンド名は公式 docs で確認したものだけ。候補をプロンプトに入れるボタンは相談キュー Q-012 の判断待ちで実装しない。見た目は terminal / desktop とも目視未確認。
