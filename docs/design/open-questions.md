- Q-002 実測メモ（2026-10-10 Ryoko・`claude -p "/context"` を空セッションで 1 回、Haiku）: 組み込み `/context` の `Tokens: 25k / 1m (2%)` は、使用カテゴリの合計（システムプロンプト 3k・システムツール 2.2k・MCP 約 1.3k・エージェント 5.9k・メモリ 6.8k・スキル 5.7k・メッセージ 10）とほぼ一致し、`Autocompact buffer 33k` と `MCP tools (deferred) 40.7k` / `System tools (deferred) 13.3k` は含まれない。つまり U-1（バッファを含むか）は組み込み `/context` では「含まない」、U-3（deferred が入るか）も「入らない」と読める。未確認: フック側 `/ctx` の `totalTokens` が同じ定義か（要・フック経由の実測）。U-2（利用者ごとの分布）は空セッション 1 回では判定不可。現行の判定式（`autoCompactThreshold - totalTokens`）はこの読みと矛盾しないため変更しない。
- Q-003（期限: mod-001 設計時）: 内訳を `summary`（推定・無料）から `full`（token-count API で正確・通信を伴う可能性）に切り替えるか（C-10）。A) summary のまま「推定値」と明記 B) `/ctx full` のような明示コマンドでのみ `full`。おすすめ: A（既定は読み取り専用・通信なしのガードレールを守る）。B は通信が要るため、希望があれば別途判断。
