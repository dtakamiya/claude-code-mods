## 結論

- 方針（だいすけ決定済み・変更なし）をそのまま画面に落とした。①使用率バーを段階色にし、圧縮点までの余裕を同じバーに載せる ②内訳は全カテゴリを割合付きで降順 ③所見は「今すぐ効く 1〜3 件」＋1 行アクション。
- 画面の並びは「使用率バー → 所見 → 内訳 → 脚注」を提案する（cinch の「次に効く改善をスコア直下へ」に倣う。好み・仮説。方針の並び順と違うので承認が要る）。
- 色はすべて型で実在確認したテーマキー（`success` / `warning` / `error` ほか）。現行 `pane-view.tsx` の生の色名 `'red'` / `'yellow'` はテーマに追従しないため置き換える。色なしでも「段階ラベル `[注意]`＋圧縮点まで N 文言＋記号」で同じ意味が読める。
- 幅・高さの出し分けは、型にある `bodyColumns`・`placement`・`scroll.bodyRows` で決められる（既存は `bodyColumns` だけ）。
- 読み取り専用・通信なしは維持。使う入力は既存の `$.session.usage({ breakdown: 'summary' })` の Snapshot のみ。

## 4. 設計

### 4.1 データ

追加の取得はない。既存の `Snapshot`（`categories`・`totalTokens`・`maxTokens`・`autoCompactThreshold`・`isAutoCompactEnabled`・`mcpTools`・`memoryFiles`・`skills` ほか）で足りる。足りないのは所見側の次の 3 項目で、実装時に `Finding` へ足す。

- `headline`: 1 行見出し（例 `メモリ 21,400（11%）`）。狭幅用に短い版も要る
- `action`: 1 行アクション（`/mcp で要否を確認`）。狭幅用に 20 桁程度の短縮版
- `tokens`: 回収できる見込みのトークン（並べ替え用。MCP・メモリは合計値、圧縮は無し）

### 4.2 使用率バー（方針①）

幅 `W` の 1 本のバーに、窓（`maxTokens`）を `W` 分割して次の 4 領域を左から並べる。

| 記号 | 領域 | 範囲 |
|---|---|---|
| `█` | 使用 | 0 〜 `totalTokens` |
| `▒` | 余裕 | `totalTokens` 〜 圧縮点（`autoCompactThreshold`） |
| `┃` | 圧縮点 | 圧縮点の位置に 1 桁。常に描く |
| `░` | バッファ | 圧縮点 〜 窓の末尾 |

- 位置は `round(量 / maxTokens × W)`。圧縮点の桁は `1 〜 W-1` に丸める。超過時（`totalTokens` > 圧縮点）は `█` が `┃` を越え、`┃` はそのまま残す。
- 自動圧縮が無効、または `autoCompactThreshold` が無いときは `┃` と `▒` を描かず、`█` と `░`（空き）だけにして、段階は使用率で出す（下表）。
- `totalTokens` にバッファが含まれるかは未確認（review の U-1）。バーは「`totalTokens` と `autoCompactThreshold` の差」を描くだけで、実余裕とは断定しない（既存 `compactionFinding` のコメントと同じ立場）。

段階（**しきい値は仮置き**。実測の裏付けなし）:

| 段階 | 自動圧縮が有効 | 無効 | 色 |
|---|---|---|---|
| 余裕 | 圧縮点までの残り > 窓の 15%（新規・仮置き `warnCompactShare`） | 使用率 < 60%（新規・仮置き） | `success` |
| 注意 | 残り ≤ 15% | 60% ≤ 使用率 < 80% | `warning` |
| 危険 | 残り ≤ 窓の 5%（既存 `nearCompactShare`） | 使用率 ≥ 80%（既存 `fallbackPercent`） | `error` |
| 超過 | 残り ≤ 0 | — | `error`（ラベルのみ違う） |

「危険」「超過」は既存の `compactionFinding`（high）と同じ条件にそろえてあり、バーと所見が食い違わない。新しく足すのは「注意」の境界 2 値だけで、`threshold-rationale.md` と同じく実測待ちの仮置きとして扱う（実装時にその表へ追記する）。

### 4.3 内訳（方針②）

- 対象: `categories` の `used`・`free`・`buffer` 全部を `tokens` 降順に 1 列で。割合は `tokens / maxTokens`（四捨五入。端数で合計が 100% にならないことがある）。
- 行: `名前 / トークン / 割合 / ミニバー`。名前は固定幅（モックは 18 桁）で `wrap="truncate-end"`、トークンと割合は右寄せ。ミニバーは `round(割合 × 16)` 桁、最小 1・上限 8。記号は使用 `█`・空き `▒`・バッファ `░`（上のバーと同じ）。
- `deferred`（窓の外）は割合が意味を持たないため、降順リストに混ぜず別行 `窓外（遅延読込） N`（fullscreen と余白があるときのみ）。

### 4.4 所見（方針③）

- 候補は `analyze()` の結果のうち `high` と `mid`。重大度順、同順位は回収トークンの多い順。上位 3 件（狭幅は 2 件）。
- 1 件 = 見出し 1 行（`[注意] メモリ 21,400（11%）`）＋アクション 1 行（`→ 長文を参照ファイルへ切り出す`）。`bodyColumns >= 68` なら 1 行に連結してよい。
- `[要対応]`（high）は、圧縮点の「危険／超過」のときだけ出る（バーと同条件）。「注意」段階ではバーのラベルが担い、所見には出さない。
- 仮説（`hypothesis`）はペインに出さない。`/ctx` のテキストには残る。ペインに出る文は観察できる数値と、その数値に対する手当てだけにする（共起を原因と書かない規則の維持）。
- 0 件なら `所見なし（今すぐ効く対応はありません）`。
- `info`（スキル一覧・エージェント・未ロード MCP）は fullscreen の「参考」に最大 3 件。

### 4.5 色（テーマキー）と色なし代替

テーマキーは型 `ThemeKey` に実在するものだけを使う（§6）。

| 用途 | 色（`color`） | 他の装飾 | 色なしの代替 |
|---|---|---|---|
| 使用率の数値 | 既定（`text`） | `bold` | 数値そのもの |
| 段階ラベル `[余裕]`〜`[超過]` | 段階色（`success`/`warning`/`error`） | `inverse`＋`bold`（ラベルだけ反転） | ラベルの**文言**が段階を言う |
| バーの `█`（使用） | 段階色 | — | `█` と `▒` `┃` `░` の**形**で領域が分かる。凡例を併記 |
| バーの `▒`（余裕） | `subtle` | — | 同上 |
| バーの `┃`（圧縮点） | `error`（超過時のみ。他は既定） | `bold` | `┃` ＋「圧縮点まで N」文言 |
| バーの `░`（バッファ） | `inactive` | `dimColor` | `░` の形 |
| 所見のラベル | high は `error`、mid は `warning` | `bold` | `[要対応]` `[注意]` の文言 |
| 所見のアクション `→` | `suggestion` | — | `→` 記号 |
| 内訳の名前・数値 | 既定 | — | — |
| 内訳の空き行 | `subtle` | — | `▒`、名前に「空き」 |
| 内訳のバッファ行 | `inactive` | `dimColor` | `░`、名前に「圧縮バッファ」 |
| 見出し（所見・内訳） | 既定 | `bold` | 見出し文字 |
| 脚注・参考・窓外 | `inactive` | `dimColor` | 文言（「推定値」） |

- 色だけで意味を持たせない（段階・重大度は必ず文言が付く）。グレー系の `subtle`/`inactive` が背景に埋もれる配色もありうるため、領域の区別は記号の形で担保する。
- バー・ラベルは同じ段階色で統一し、1 画面で使う色相は `success`/`warning`/`error` と `suggestion` に絞る。

### 4.6 幅・高さの出し分け

入力: `e.props.bodyColumns`（枠の内側の桁数）、`e.props.placement`（`dock` か `inline`）、`e.props.scroll.bodyRows`（本体が使える行数）。いずれも型で読み取り専用の値として実在する（§6）。

**幅**（`bodyColumns`。境界は仮置き・名前付き定数にする）:

| 区分 | 条件 | 描き方 |
|---|---|---|
| 狭幅 | `< 40`（既存 `NARROW_BODY_COLUMNS`） | バー幅 = `bodyColumns - 4`（両端の `[` `]` と余白を除く。最大 40）。凡例なし。内訳は名前＋割合のみ。所見は 2 件・短縮版 |
| 通常 | `40 〜 67` | バー幅 40。凡例あり。内訳は名前・トークン・割合・ミニバー。所見は見出し行＋アクション行の 2 行構成 |
| 広め | `>= 68`（新規・仮置き `WIDE_BODY_COLUMNS`） | 通常に加え、所見を 1 行に連結。ヘッダ行の右端に段階ラベルと「圧縮点まで」を寄せる |

内訳は幅によらず 1 列。2 列組はカテゴリ名が最長 18 桁・行が約 40 桁で、72 桁に収まらないため見送り（YAGNI）。

**高さ**（`scroll.bodyRows`）: 必要行数が `bodyRows` を超えるとき、次の順で省く。1 の使用率バーと 2 の所見 1 件目は**省かない**。

1. 参考（info）→ 2. 窓外行 → 3. 脚注 → 4. 凡例 → 5. 所見の 3 件目・2 件目 → 6. 内訳の下位を `他 n 件 合計 x%` に畳む（割合の合計は保つ）。

`placement` は分岐に使わず、高さと幅で足りる（`inline` は「枠が木に合わせて伸びる」ので `bodyRows` が上限、`dock` は fullscreen の横置き、と型にある。縦の余白は目視未確認）。`placement` は fullscreen のモックの前提を示すだけ。

操作要素は置かない（`Button`・`Input` なし）。スクロールはエンジンが持ち、フォーカス中の矢印キーで動く（型 `scroll`）。

## 8. ガードレール

- 読み取り専用。`$.process.run`・`$.fs` 書込・ネットワークは使わない。入力は `$.session.usage({ breakdown: 'summary' })`（ローカル推定・送信なし）のみ。
- 時系列の保存（スパークライン等）は新しい永続化が要るため本設計に含めない。
- 実データ・個人名・秘密値を含めない。モックはすべて架空（`github` は一般的なサーバー名の例）。
- メモリのパスは出さない（ファイル名＋type への短縮方針を維持）。
